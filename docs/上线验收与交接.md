## 在Render控制台完成

1. 在现有服务的Settings核对Repository是否为上述仓库，Branch是否为更新分支；不新建替代服务。
2. 若旧站仍用应用磁盘上的JSON/CSV，先导出旧站记录到项目组的私有位置。不要在未备份时触发旧容器重建。
3. 先在Render查看是否已有Postgres资源。没有时，可在控制台选择“+ New → Postgres”，地域选为与网页服务相同，并自行确认所选方案的保留期限、备份能力和费用。数据库可用后，从该数据库页的Connect菜单找到Internal Database URL，直接填到网页服务Environment中名为DATABASE_URL的变量里并保存。不要把连接串发到聊天、写进仓库或截图。[官方创建与连接说明](https://render.com/docs/postgresql-creating-connecting)
4. 配置APP_ENV=production、足够长的SECRET_KEY、ADMIN_USERNAME与ADMIN_PASSWORD_HASH。已有SECRET_KEY应保留；密码哈希可在自己电脑运行scripts/hash_admin_password.py生成。
5. Build Command为pip install -r requirements-render.txt；Start Command为python scripts/start_production.py；Health Check为/health。仓库.python-version选择Python 3.14；服务中如有优先级更高的PYTHON_VERSION变量，应先核对。[官方Python版本说明](https://render.com/docs/python-version)
6. 如需进行公网功能验收，可临时设置ALLOW_TEST_MODE=1，并用?test=1链接创建TEST记录。测试完成后改回0，勿用正式入口做演示采样。
7. 先看迁移及启动日志，再检查首页、健康检查、后台登录与测试回执。不要在日志或公开问题中粘贴研究记录。

这些设置需要在账号内确认；本地文件准备和GitHub提交不等于Render已采用该代码。

## 只读初检

```powershell
.\.venv\Scripts\python.exe scripts/verify_deployment.py https://xinyue-risk-control.onrender.com
```

工具会识别公网首页是旧8页申请还是新学习门户。旧版核对首页8页结构与界面版本；新版再核对`/apply`的8页结构、`/assessment`的16题结构，以及`platform.css`是否与本地文件哈希一致。工具还读取`/health`、界面样式和未登录后台API，不创建参与记录。输出中的`read_only_checks_passed`仅表示这些只读检查通过，不能代替实际提交和持久化验收。
