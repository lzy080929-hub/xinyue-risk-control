# 信跃大学生金融素养平台改版设计

日期：2026年10月26日。交付范围为产品设计和可点击交互原型；本文件中的新增模块、题库、版本和字段是拟议方案，不代表已经写入线上数据库或发布。现有申请、采集和历史记录保留。

## 1. 平台定位与整体结构

品牌建议：**信跃｜大学生金融素养成长平台**。

首页主标题：**学会管理生活费，看懂每一次借贷。**

平台围绕“测一测—学一学—练一练”组织内容。首页不再直接呈现一张申请表；顶部导航包括首页、金融素养测评、知识科普、信贷申请体验与学习工具。研究者入口放在页脚。保持深蓝主色、灰底白色内容区，增加适合学生阅读的青绿色辅助色；不使用银行标识、不编造服务人数或合作机构。

| 板块 | 访客要解决的问题 | 首版内容 |
| --- | --- | --- |
| 金融素养测评 | 我哪些知识还不熟悉？ | 16道自编客观学习题，4个知识主题，结果解释与学习推荐 |
| 知识科普 | 怎样理解预算、借贷成本和金融风险？ | 12个短主题，校园情境、解释、行动提示与来源 |
| 信贷申请体验 | 申请时应看什么、确认什么？ | 保留8页，平台展示统一情境条款，第6页增加承诺复制粘贴 |
| 学习工具 | 能不能把这些概念算出来？ | 借贷成本试算、生活费预算、反诈情境判断 |
| 我的学习 | 我看过什么、还需要补什么？ | 当前浏览器的学习进度和错题，不强制注册账号 |
| 项目介绍 | 谁运营、怎样使用数据？ | 项目背景、测评说明、隐私说明与反馈方式 |

首版不增加论坛、真实贷款推荐、产品导流、复杂积分商城或“个人信用评分”。这些会增加维护工作，也不直接服务当前目标。

## 2. 首页设计

首页顺序：顶部导航 → 一段主视觉与两个学习按钮 → 三大模块卡片 → 三篇精选科普 → 校园情境工具 → 项目与数据说明。

三个主要入口同等清楚，默认主按钮为“开始金融素养测评”，第二按钮为“浏览知识科普”。申请体验卡标出8页流程，避免把整个平台做成鼓励借款的营销页面。

文案示例：

> 从一笔生活费预算开始，了解借贷成本、识别常见骗局，在申请体验中练习作出知情选择。

不展示没有证据的“超过90%同龄人”“专业认证金融素养等级”“累计服务万人”等内容。

## 3. 金融素养测评

### 3.1 测什么

参考OECD/INFE关于知识、行为与态度的测量思路；首版将**可客观判分的学习题**与**可选的自报习惯**分开。现有29题是还款相关的TPB量表，不能改名充当金融素养测评。

客观学习题采用4主题×4题，共16题，预计用时5—8分钟（设计目标，需试填验证）：

| 主题 | 覆盖概念 |
| --- | --- |
| 预算与储蓄 | 可支配资金、必要支出、应急安排、记账 |
| 借贷与成本 | 本金与利息、年/月利率、分期本金变化、相关费用 |
| 金融安全 | 验证码、冒充客服、保证删除准确不良记录的收费承诺、信息授权 |
| 风险与权益 | 高收益承诺、购买力、分散风险、阅读条款 |

每题有“暂不确定”选项，作答后统一给解释。正确率=答对题数/16×100%；各主题报告答对几题。不要把跳过当真实错误答案存储：保存选择、是否作答与判分结果；学习计分中未答不计为答对，结果同时报告完成度。

结果文案为“本次学习测验正确率”“建议先学习：借贷成本”等。题库标明“平台自编学习测验”，不声称已通过信效度验证、等同OECD标准分或能评估个人信用。

可选自报习惯如记账、消费前比较总成本、查看授权范围等，单独展示建议；不与客观题机械相加成一个未经验证的综合分数。

### 3.2 与研究申请分开

普通学习路径可以“测评→解释→科普→申请体验”。研究招募链接应直接进入申请，主要测量完成前不强制学习和展示答案解析，否则知识教学本身可能改变填写行为与29题答案。

新协议在同意后询问申请前是否已经学习过平台内容，记录自报暴露情况。未同意前不安装研究行为追踪，不用后台浏览日志暗中重建学习路径。不同路径、版本和先前学习情况分开分析。

## 4. 知识科普内容

首版12个短主题：生活费预算、应急资金、消费前比较、利息与复利、年利率与分期、费用与总成本、最低还款、借新还旧、冒充客服、征信相关骗局、授权与隐私、收益与风险。

每篇采用“校园情境→概念解释→小算例或判断→行动提示→权威来源与核对日期”的结构。建议每篇3—5分钟可读完，避免大段法规堆砌。

不做实时产品利率榜和具体贷款推荐。数值算例明确假设，不把某个预算比例包装成适合所有学生的标准。遇到真实产品须引导核对合同与正规机构说明。

## 5. 利率为什么不该由自己选

目前的8.5%、10.5%、12.5%来自旧原型的下拉控件。它没有对应的定价模型、机构报价或随机分组，不能解释成银行真实给出的价格，也不能据此识别利率对行为的因果影响。

**推荐首版：平台给定统一的教学情境，参与者确认条款。**

- 删除利率下拉框，展示只读条款卡。
- 原型示例采用名义年利率6%、按月等额本息、无额外费用，仅用于教学假设，并非现实银行报价；正式研究也可保留原8.5%作为统一值。数值需在新协议固定。
- 展示金额、期限、计息与还款方式、预计每期还款、总利息、总还款。费用为0也是明确假设，不能遗漏后称“完整成本”。
- 月利率r=名义年利率/12，等额本息月供A=P×r/[1-(1+r)^(-n)]。若展示复利口径的有效年化率，应另标(1+r)^12-1，不把名义与有效口径混为一谈。
- 示例：10000元、12个月、名义年利率6%、按月计息、无其他费用，月供约860.66元、总利息约327.97元，有效年化率约6.17%；末期按实际舍入调整。

若后续研究利率情境的影响，应由服务器随机分配预设组别，记录分配方案、组别和版本，刷新不重新抽签，后台复核分组；不是让用户自己挑一个。未建真实定价模型时，不根据收入、修改次数或量表答案生成“你的风险利率”。

借贷成本计算器中可以自由改变利率进行教学对比，但它与研究申请条款分开，不能悄悄把计算器的选择回写成研究情境。

## 6. 申请页文字与8页流程

可以移除页头反复出现的“科研模拟 · 非真实贷款”徽标，以及每页重复的宣传性警示。页头改为“信跃｜金融素养成长平台”，入口与标题使用“信贷申请体验”。

进入前的说明仍需清楚写明：**本体验不发生真实借贷或资金交易，不查询征信；同意后保存所填信息和已说明的操作事件。** 这影响访客能否知情决定参与，不能把体验页伪装成真实放贷页面。

原8页顺序保留：

1. 参与说明与同意。
2. 申请人信息。
3. 收入与总负债。
4. 贷款需求。
5. 平台给定条款与成本确认。
6. 信息核对＋复制粘贴本人确认语。
7. 原29题的1—15题。
8. 原29题的16—29题，提交并等待服务器回执。

量表原文、顺序及反向题不变。RRT放在这8页成功保存之后，作为独立、可跳过的邀请；它不阻塞已完成申请的回执。

## 7. 本人承诺的复制粘贴

建议显示以下确认语，并提供“复制确认语”按钮和粘贴框：

> 本人已阅读本次申请说明和展示条款，确认以上信息为本人自主填写。

这里不要求真实姓名，不加入“无条件接受真实借款合同”等内容。避免使用“我保证一定按时还款”作为统一前置要求：它会直接提示29题所测的还款意向，可能引入承诺效应。

交互规则：点击复制→粘贴或手动输入→本地核对固定文本→勾选确认→下一页。不支持剪贴板写入时允许长按复制或手动输入；不因没有paste事件就判定违规。

数据规则：只保存确认是否完成、确认语版本及定义过的事件次数/时长；不读取系统剪贴板，不上传粘贴框正文。该框与普通申请字段分开汇总。**页面要求产生的粘贴不能当作普通粘贴风险特征。**

如确实要研究承诺的影响，可设计有/无承诺对照并记录分组；若所有新版访客都有此步骤，只能描述新版结果，不能直接把新旧差异解释为承诺造成的效果。

## 8. RRT独立模块

### 8.1 目标与问题口径

RRT用于估计群体敏感经历的比例，不产生个人逾期标签，不是还款意愿真值。

建议题目定稿时明确：过去12个月、哪些个人信用借款、到期和约定宽限期怎样算。示例口径为“过去12个月，你是否曾未在约定还款日（含已约定宽限期）前支付到期个人信用借款的应付金额？”没有到期借款经历者按否作答。

这样估计的是**调查对象总体中的这类经历比例**，不是“所有借款人的违约率”，更不等于征信核验结果。示例定义需要写入方案版本，不能与旧方案“曾经逾期”混算。

### 8.2 浏览器上的私下随机

先用不敏感例子说明规则，允许跳过。点击一次“开始私下随机”：

- 50%概率：按真实情况回答敏感题。
- 另50%概率：回答另一个独立公平随机结果是否为正面，按该结果选择是/否。

两次随机使用浏览器可靠随机源；分支和结果只在本地内存使用。旧材料中的“心里想1—100”“手机尾号奇偶”不能直接假设各有50%，本方案不沿用该假设。

界面两种分支使用同一页面与提交入口。关闭主申请细粒度追踪，不发送分支、随机结果、种子、回答过程时长或题目正文；这些也不能写入URL、浏览器持久存储或错误监控。刷新不恢复私下随机结果；如重新开始须明确操作，不假装恢复原抽签。

### 8.3 保存、去重与关联边界

使用独立RRT响应表，只保存混合是/否或跳过、方案版本、测试标识与必要的粗粒度批次。不要把RRT回答直接拼到个人申请分析CSV。

若使用一次性调查凭证防重放，应把凭证兑付记录与RRT响应分开，不在响应表保存主申请编号、凭证或精确作答时间。不能承诺因此绝对不可关联：凭证签发、网络与基础设施日志仍可能提供关联线索，需如实说明边界。

同意与是否跳过独立记录；RRT失败不回滚申请，不为了取得RRT答案扣住主申请成功页。测试标识由签发凭证时的服务端状态确定，不让客户端随意混入正式组。

### 8.4 后台估计

有效混合回答中“是”的比例为λ，敏感题概率θ=0.5，无关随机题“是”的概率π=0.5。则λ=0.5P+0.25，原始估计P̂=2λ-0.5。

后台同时显示有效回答数、跳过数、方案版本、是比例、原始估计及不确定性。可先对λ计算Wilson区间，再线性变换端点；原始点估计或区间超出[0,1]时保留并解释，另列的约束结果必须清楚标注。小样本、跳过选择和不按随机指令作答都限制解释，不能只显示一个漂亮百分比。

不同版本及测试记录不混算；不把P̂分配给某个人，也不按它把最低量表分数的一部分人贴成“逾期者”。

## 9. 研究版本与旧记录兼容

建议新增版本而不是改写旧记录：平台platform-v1、客观题literacy-learning-v1、申请study-v4-fixedrate、确认语pledge-v1、RRT rrt-uq50-v1（均为拟议名称）。量表保持repayment-29-v1及原计分版本。

旧申请继续保留旧表单、旧实验及旧界面版本。新服务器需要根据会话版本选择对应校验规则；不能仅改一个全局版本就让所有旧标签页恢复失败。旧草稿不补写已完成承诺或利率分配。

拟议新增申请字段：情境版本、不可变的指定利率与分配方式、确认语版本与完成状态、申请前学习情况、学习/研究路径。利率由服务器核验，不信任客户端回传的任意利率。数据库结构变化通过备份和迁移完成。

拟议路由：首页/、测评/assessment、科普/learn、工具/tools、申请/apply、独立调查/rrt、研究者/admin。旧分享链接和正在填写的旧会话要提供兼容入口，不能在上线首页时使其丢失当前填写进度。

## 10. 开发与验收顺序

1. 先增加门户、科普和独立学习测验，保留现有申请与采集。
2. 新协议实现只读条款、明确口径的成本试算与第6页确认语；验证旧会话兼容。
3. RRT独立建表和提交，检查浏览器网络与持久存储中没有分支/随机结果；验算群体估计及边界。
4. 备份后迁移；独立库进行API与浏览器流程验证，再发布并核对公网回执、导出与重启保留。

验收重点：学习答题数据与29题分开；未同意不采集研究行为；协议要求的粘贴不混入原普通字段指标；RRT不接入细粒度追踪；客户端不能篡改情境利率；测试记录不计正式样本。

## 11. 本次可点击原型

`design/college-platform/index.html`可在本机直接用浏览器打开，不需要启动Flask。包括首页、16题学习测验、12个科普主题、成本试算、申请改版示意、确认语复制粘贴和RRT随机流程预览。

原型不发送研究数据、不写数据库、不替换现有线上页面；新增计分仅为学习演示。已上线的申请仍以当前生产版本为准。
